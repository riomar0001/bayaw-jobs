# BayawSec: role responsibilities and tickets

Roles follow the Deliverable 1 roles table. **Owners are not final**, so this page names roles, not people.
When someone takes a ticket, put their name on the matching issue or board card. Don't edit names into this file.

**How to read a ticket**

- **Size:** S (under 2 hours), M (half a day), L (1 to 2 days)
- **Depends on:** tickets that must be done first
- **Done when:** the acceptance check. A reviewer from another role ticks it off.

**Status today:** the backend for all six core features is built and tested locally (see [architecture.md](architecture.md)).
What's left is the frontend, real testing, prompt work, deployment and the documents.

| Role                 | Main responsibilities                                          | Tickets      |
| -------------------- | -------------------------------------------------------------- | ------------ |
| Project lead         | Coordination, approvals, documentation, presentation           | PL-1 … PL-8  |
| Frontend developer   | BayawSec admin pages, dashboard, report views                  | FE-1 … FE-16 |
| Backend and database | API, data model, tool integration, deployment                  | BE-1 … BE-10 |
| Security tester      | Reconnaissance, scanning, manual tests, verification, evidence | ST-1 … ST-11 |
| AI integration       | Prompts, AI quality, data handling, AI documentation           | AI-1 … AI-8  |

## AI integration (AI)

Work in `server/src/services/assessment/ai/`. Edit **`prompts.example.ts`** (the committed template). Its
`TODO(AI integration)` comments list what each prompt must cover. To test a change locally, delete your local `prompts.ts`
and run `npm run dev` to regenerate it from the template. Don't change the reply fields in `schemas.ts` without agreeing with
the backend and frontend roles, because the database and UI depend on them.
